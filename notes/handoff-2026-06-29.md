## 0. TL;DR

We built **`notebooks/partialGeneration.ipynb` (s4)** — the step that turns each model into a **training
pair**: a complete colored **ground truth (GT)** and **PCN-style partial** scans. We used
`grill-with-docs` to lock the spec first. The load-bearing decision: partials are generated **faithfully,
the way PCN does it** — render a 2.5D depth image **from the mesh** and back-project it — and we build
**three** partial methods and ship all of them to **compare** (don't pick one yet). The risky camera math
is **unit-tested locally and passes**; the Open3D/Colab parts are written but **not yet run on Colab**.

## 2. The decisions, in one place (the grilling outcomes)

- **Partial = FAITHFUL PCN.** Render depth from the **mesh** (Open3D `RaycastingScene`) + back-project,
  **8 random seeded viewpoints**, variable size, **not a subset of the GT** (PCN §3/§5.1). _(We corrected an
  earlier "hidden-point-removal on the point cloud" idea — PCN renders the mesh, not a cloud.)_
- **Partials carry color (`xyzrgb`).** This is the colored-completion study; PCN is geometry-only. `xyzrgb`
  is a superset of `xyz`, so the geometry-only PoinTr baseline just ignores `rgb` and the colored experiments
  use it — **one dataset serves every milestone**.
- **Three methods, ship all, compare with the supervisor** (ADR-0005):
  - `meshray_nn` *(reference)* — faithful raycast geometry + color by nearest-neighbour from the cleaned
    dense cloud (sub-mm-exact, robust).
  - `meshray_tex` — same geometry + **texture** color at the exact ray-hit (brittle → **falls back to NN**).
  - `ptproj` — project the dense colored cloud through the same camera + z-buffer; **direct** color, but
    **sees through** gaps on thin parts and is a subset of the dense cloud.
- **Same 8 viewpoints across all methods** → a comparison isolates the *method*, not the camera.
  `meshray_nn` vs `meshray_tex` = pure **color** test; `meshray_*` vs `ptproj` = pure **geometry** test.
- **GT** via s3's `color_aware_sample` (FPS), default **16384** — ⚠ **confirm against the PoinTr config**
  (s3 used 8192). Native `model_normalized` frame; both halves share it.
- **Output:** `data_s4/{complete/<synset>/<id>.ply, partial/<method>/<synset>/<id>/00..07.ply}` +
  `manifest.csv` + `viewpoints.csv`.

## 3. Validated vs needs-Colab

- **Validated locally (numpy):** camera round-trip (project↔ray, err 1e-17), z-buffer occlusion, viewpoints
  on the sphere, and `ptproj` occlusion-vs-density (needs >~1 pt/pixel; **512² + ~1M dense ≈ 4 pts/px = good
  occlusion**; raising resolution *increases* see-through).
- **NOT yet run (needs Colab/Open3D):** the `RaycastingScene` calls (`raycast_view`), `meshray_tex` texture/UV
  sampling (most brittle — barycentric weight order + the OBJ v-flip want eyeballing), the Plotly views, and
  the full batch. This is the same "written, syntax-clean, debug-on-Colab" state s2/s3 shipped in.
